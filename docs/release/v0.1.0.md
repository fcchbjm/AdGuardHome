# v0.1.0 — 自编号首版：上游 v1.0.0 同步、client_v2、PPv2 UI 与 dnsproxy v0.84.0

**`v0.1.0` 是本 fork 的自编号版本**，与上游 AdGuard Home 的版本号相互独立。本版内容对应上游 **`v1.0.0`**（2026-11-19，`7d2f42b0`），但 fork 不沿用上游 1.x 编号。

打 tag 前请完成第三方审查与提交。

## 摘要

- 同步 **upstream `v1.0.0`**（自 `369d4761` 起 **100 commits / 771 files**，+53126 / −19135）
- DNS 运行时升级到 **`github.com/fcchbjm/dnsproxy` v0.84.0**（基于上游 dnsproxy v0.86.0 + master 至 `657a4c4`，叠加 fork 加固）
- Go 工具链 **1.27.4**；`godebug multipathtcp=0`（CVE-2026-98432 缓解）
- 发行物继续嵌入 **`client_v2`（SolidJS）**，含 PPv2 DNS 设置
- 保持 fork 发行语义：本仓库 Release + `ghcr.io/fcchbjm/adguardhome`，release 二进制默认检查本仓库 `version.json`

## 上游 v1.0.0 带来的变化（本版一并纳入）

### 发行模式与工具链

- 上游改为「小版本可含不兼容变更」的新发行节奏；**配置 schema 不变，无需迁移**
- Go 1.27.4（含 1.27.3 / 1.27.4 安全修复）；**不再支持 macOS 13**
- 上游新 CI（`build.yaml` / `release.yaml` 等）带 `AdGuardSoftwareLimited` 守卫与私有 runner，**fork 继续使用自己的 workflow**

### 默认值

- 新安装默认上游/bootstrap 由 **Quad9 改为 Cloudflare**：`https://cloudflare-dns.com/dns-query` + `1.1.1.1`、`1.0.0.1`、`2606:4700:4700::1111`、`2606:4700:4700::1001`
- **已有配置不会被自动迁移**；如需继续使用 Quad9，请手动保留

### 客户端设置语义（新 UI）

- 「使用全局设置」仅作用于 **Protection**
- Blocked services 拆出独立的「使用全局阻断服务」开关
- 上游 DNS 与 DNS 缓存**始终可编辑**

### 废弃 API / 参数 / CLI flag **已移除**

- HTTP API：`blocked_services/list|services|set`、`clients/find`、`i18n/current_language|change_language`、`querylog_info|querylog_config`、`stats_info|stats_config`、`safesearch/enable|disable`
- 属性/参数：querylog 的 `filterId` / `rule`、`check_host` 的 `filter_id` / `rule`、client 的 `safesearch_enabled`、querylog 的 `response_status`
- `upstream_mode` 的空值不再合法
- CLI：`--host` / `-h`（仅保留给帮助）、`--port` / `-p`、`--no-mem-optimization`、`--no-etc-hosts`

### 修复（节选）

DoQ 资源耗尽加固、DHCP v4/v6 保存与租约、ClientID/CIDR 校验、DDR 的 SVCB 记录、schedule 时钟变更、TCP 前缀短读、`log.enabled: false`、`--check-config` 首启、绑定忙端口 panic、CLI 更新 panic、querylog 分页 panic、客户端数据竞态等。

## dnsproxy v0.84.0 升级要点

- `upstream.Upstream.Exchange` 与 `ExchangeAll` / `ExchangeParallel` 增加 `ctx`
- `dnsproxy/fastip` 变为 `internal`，AGH 侧改用自有常量
- `proxy.Proxy` 不再内嵌 `Config`，配置读取改走 `Config` 副本 / 服务端字段
- **`proxy.New()` 新增 `Config.Validate()`**：无上游、空 `Fallbacks`（非 nil）、非法 `upstream_mode`、BasicAuth 无监听地址等会在启动前直接失败
- `ratelimit.Config.MaxSize` 必须 > 0（本 fork 使用 `ratelimit.DefaultMaxSize`）
- `CacheSizeBytes` 类型改为 `datasize.ByteSize`
- 并行查询不再把 **SERVFAIL** 当作成功；空/非权威响应不再入缓存；SERVFAIL 最多缓存 30s
- **`TrustedProxies` 为 nil 时归一化为空集（fail-closed）**：本 fork 默认已显式设置环回网段
- 已知问题：`quic-go v0.65.0` 的 0-RTT 竞态在 `-race` 下可能间歇失败，**不是 AGH 侧回归**

# v0.1.0 — First self-numbered release: upstream v1.0.0 sync, client_v2, PPv2 UI, dnsproxy v0.84.0

**`v0.1.0` is this fork's own version number**, independent of upstream AdGuard Home versions. Its content corresponds to upstream **`v1.0.0`** (2026-11-19, `7d2f42b0`), without adopting upstream's 1.x numbering.

## Summary

- Synced **upstream `v1.0.0`** (**100 commits / 771 files** since `369d4761`, +53126 / −19135)
- Runtime: **`github.com/fcchbjm/dnsproxy` v0.84.0** (upstream dnsproxy v0.86.0 + master through `657a4c4`, plus fork hardening)
- Go **1.27.4**; `godebug multipathtcp=0` (CVE-2026-98432 mitigation)
- Releases keep embedding **`client_v2` (SolidJS)** with PPv2 DNS settings
- Fork release semantics unchanged: this repo's Releases + `ghcr.io/fcchbjm/adguardhome`

## Upstream v1.0.0 changes included

- New release model (minor releases may include incompatible changes); **config schema unchanged**
- Go 1.27.4; **macOS 13 dropped**
- New installs default to **Cloudflare DNS** upstream/bootstrap (existing configs are **not** migrated)
- New UI client settings: "Use global settings" applies to Protection only; blocked services get their own switch; upstreams and cache always editable
- **Removed** deprecated HTTP APIs, properties/parameters, empty `upstream_mode`, and CLI flags `--host`/`-h`, `--port`/`-p`, `--no-mem-optimization`, `--no-etc-hosts`
- Large set of fixes: DoQ hardening, DHCP v4/v6, ClientID validation, DDR SVCB, schedules, TCP prefix reads, `log.enabled`, `--check-config`, busy-port panic, CLI update panic, querylog pagination panic, client data race

## dnsproxy v0.84.0 highlights

- `Exchange` / `ExchangeAll` / `ExchangeParallel` now take `ctx`
- `fastip` moved to `internal`
- `proxy.Proxy` no longer embeds `Config`
- `proxy.New()` validates its config and may fail early
- `ratelimit.Config.MaxSize` must be > 0
- `CacheSizeBytes` is now `datasize.ByteSize`
- Parallel mode no longer treats SERVFAIL as success; caching tightened
- Nil `TrustedProxies` fails closed (fork already sets loopback defaults)

## Upgrade

1. Stop the service; back up config/data.
2. Replace the binary or `docker pull ghcr.io/fcchbjm/adguardhome:v0.1.0`.
3. Verify the new UI, PPv2 settings, and upstream/bootstrap defaults (only new installs change).
4. Migrate scripts that call removed APIs or CLI flags.
